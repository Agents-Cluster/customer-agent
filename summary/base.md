# 基本概念

128k上下文
1m约等于75万汉字
国产三强: ds、glm、qwen

基于实时降低大模型幻觉
如何保证知识库新鲜度: 更新文档 or 续训

# RAG流程

## 数据支撑
1. 数据准备
2. 数据切片 -> 向量化(embedding: 向量模型 -> bgem3 )(稠密向量[相似度]、稀疏向量[关键词], 统称混合检索)
3. 存入向量库(milvus)
4. 初始化和构建向量库

## 用户检索
1. 用户问题 -> 向量化
2. context(用户问题 + 检索结果) = prompt 提供给LLM
3. LLM输出结果

## qa
1. embedding(向量内嵌模型: bge-m3)
2. rerank(重排模型: ), 精排、粗排, 过滤无关信息、提升上下文信息相关性
3. 多路检索(向量检索, MCP网络搜索, HyDE检索[假设性检索: 用户输入不全]), 从向量库中检索的数据可以融合
4. 元数据
5. minIO: 文件服务器
6. milvus: 向量数据库
7. loguru: 日志库
8. pytorch: 为向量模型提供运行环境
9. minerU: pdf转md文件, 再解析md文件
10. 噪声: 不相关数据
11. 挂起: 暂停服务, 效果比关机、开机服务快很多、恢复速度快, 但存在一个问题: 挂起是停留在当前时间超过十五分钟后再恢复与当前系统时间不一致操作就会失败
12. 限流的实现: 
- 每次请求放入队列(放的是请求时间戳)、设置最大次数、设置时间、(固定窗口、滑动窗口)
- 关于大模型限流函数: apply_api_rate_limit 这一个函数解决所有问题

# 卡点
1. 文件标题存在两类产品名称, 导致检索失败, LLM无法召回有效内容
2. 回答准确率(保证原始资料能被AI精准找到、看懂、被用来做决策): 核心六点: 数据结构化 -> 语义切片 -> 多路召回 -> 混合检索 -> 假设增强 -> 精排裁决
3. 切片中断
